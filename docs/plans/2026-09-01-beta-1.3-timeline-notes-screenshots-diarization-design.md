# MeetingNotes Beta 1.3 时间轴笔记、截图与说话人分离设计

日期：2026-09-01
目标版本：会议记录 Beta 1.3.0 (17)

## 目标

在不改变正式版 1.2.0 (16) 已验证功能和原有原生磨砂界面的前提下，为下一版 Beta 增加：

1. 录制期间按会议时间添加并自动保存文字笔记。
2. 录制期间截取鼠标所在显示器，并将截图关联到同一会议时间轴。
3. 让用户笔记参与重点总结和完整纪要。
4. 将笔记与截图同步到 Notion，同时确保截图绝不发送给 DeepSeek。
5. 使用真实会议验证过的 FluidAudio 聚类阈值改善多人会议说话人合并。

## 不在本次范围内

以下能力已经完成，本次只做回归验证，不重复开发或重构：

- 转录、重点总结和完整纪要原位编辑及自动保存。
- 当前会议内的精确批量替换，包括转录、说话人、负责人、总结和纪要。
- Notion 显式同步以及 MeetingNotes 管理区块的替换更新。
- GitHub/Sparkle 免费应用内更新。
- 高精度模型 `openai_whisper-large-v3`、模型缓存恢复、重试和公共下载选择器。
- 模型准备完成前阻止创建无法控制的会议。
- 现有音频设备兼容、智能诊断、Adaptive 麦克风和硬超时实现。

本次不强制说话人数，不改变 Whisper 解码策略，不修改转录分块、PCM 增益、录音架构或正式版身份。

## 架构原则

- 会议记录仍是所有转录、文档、笔记和截图的唯一所有者。
- 笔记和截图都是带会议相对时间的时间轴事件。
- 本地持久化与远端同步分离：本地编辑即时保存，Notion 只在用户点击“同步到 Notion”时更新。
- DeepSeek 只接收允许的文字数据；截图的内容、路径、文件名、附件标识和元数据都不得进入请求。
- UI 在现有视图中渐进增强，不增加新的主窗口或改变信息架构。

## 数据模型

为会议增加两类持久化子记录：

### MeetingNoteRecord

- 稳定 UUID。
- 所属 meeting ID。
- 会议相对时间，使用与录音时间轴一致的非负秒数。
- 笔记文字。
- 创建时间和更新时间。
- 稳定排序字段，用于相同时间戳时保持顺序。

笔记文字每次发生键盘变化时通过现有自动保存模式持久化。保存失败时保留内存草稿并允许重试。

### MeetingScreenshotRecord

- 稳定 UUID。
- 所属 meeting ID。
- 会议相对时间。
- MeetingNotes 管理目录下的相对文件标识，不在业务记录中保存用户绝对路径。
- 像素尺寸、文件大小、创建时间和稳定排序字段。

只有本地原图成功原子落盘后才创建数据库记录。删除会议时级联删除笔记记录、截图记录及其 MeetingNotes 管理的图片文件。

### 统一时间轴

详情页在展示层合并转录条目、文字笔记和截图记录，并按：

1. 会议相对时间；
2. 稳定排序字段；
3. UUID；

进行稳定排序。持久化模型不把不同事件强行合并成一种难以演进的通用 JSON 结构。

## 录制悬浮窗交互

保持当前原生磨砂透明悬浮窗、圆角、轻量阴影和系统图标。在现有控制区增加两个紧凑按钮：

### 笔记按钮

- 点击瞬间从当前活动会议时间轴取得时间戳。
- 在悬浮窗下方展开单行紧凑输入框并取得焦点。
- 每次文字变化自动保存，不增加保存按钮。
- Enter 收起输入框；会议录音和转录持续运行。
- 保存失败只显示轻量重试状态，不关闭输入框或中断会议。

### 截图按钮

- 点击瞬间取得会议时间戳和鼠标当前所在显示器。
- 截取该显示器的完整画面，不截取其他显示器。
- 成功后仅显示短暂勾选反馈，不弹出大预览，不抢占输入焦点。
- 权限或捕获失败只产生非阻塞提示；缺少权限时提供系统设置入口，会议继续运行。
- 不改变现有系统音频 ScreenCaptureKit 会话的所有权和生命周期。

## 会议详情页交互

不增加新的复杂页面。笔记和截图以内联事件插入现有转录时间轴：

- 笔记显示为带时间戳的磨砂文字卡片，可原位编辑并自动保存。
- 截图显示为带时间戳的小缩略图，点击使用系统原生预览查看本地原图。
- 笔记和截图提供右键删除操作。
- 删除失败时保留可见记录并显示错误，不制造数据库与文件系统不一致。

## 总结与 DeepSeek 数据流

生成或重新生成重点总结和完整纪要时：

- 使用当前最新的用户笔记文字及会议时间戳。
- 在提示中明确标记为“用户主动记录”，使其可补充负责人、决定事项、行动项和关键上下文。
- 继续使用当前最新的已编辑转录及说话人姓名。

截图不参与 DeepSeek：

- 不发送图片二进制。
- 不发送 OCR、图片描述或缩略图。
- 不发送本地路径、文件名、尺寸、哈希或附件 ID。
- 通过请求构建器类型边界和负向测试保证该约束，而不是只依赖 UI 隐藏。

## Notion 同步

继续复用现有“显式同步 + 替换 MeetingNotes 管理区块”机制。

每次用户点击同步时，建立一个最新的规范快照，包含：

- 已编辑转录及说话人姓名。
- 重点总结和完整纪要。
- 按会议时间排序的笔记和截图。

Notion 中增加“会议时间轴”管理区块：

- 笔记以时间戳加文字呈现。
- 截图以时间戳加图片呈现。
- 再次同步替换旧的 MeetingNotes 管理内容，不重复叠加。
- 用户在页面中手工添加的非管理内容不删除。

### 截图上传流程

1. 本机原图始终保留。
2. 同步时在临时目录生成 JPEG 副本。
3. 先降低 JPEG 质量，必要时再等比例缩小，确保每张不超过 4.5 MiB。
4. 先完成当前快照的全部截图上传，再开始替换 Notion 管理区块。
5. 任一上传失败时保持 Notion 旧内容和所有本地数据，允许直接重试。
6. 成功或失败后都删除临时压缩副本。

现有 Notion checkpoint/恢复语义继续负责区块替换失败时的可恢复性。

## FluidAudio 说话人分离

当前应用使用 `OfflineDiarizerManager()` 的默认阈值 0.6。两份本地真实会议的脱敏对照表明：

- 一个明显合并的会议在 0.6 下第二位说话人仅约 2.2 秒；使用 0.7045655 后恢复到约 149.8 秒。
- 另一个长时多人会议使用 0.7045655 后得到四个主要说话人和一个约一秒的短片段，与原始多人分布基本一致。

本次只将管理器构造改为显式：

```swift
OfflineDiarizerManager(
    config: OfflineDiarizerConfig(
        clusteringThreshold: 0.7045655
    )
)
```

不设置最少或最多说话人数，不自动删除短说话片段，不修改后续 `room-N` 映射。

## 错误处理与一致性

- 笔记保存使用与当前会议编辑相同的串行自动保存和重试原则。
- 截图写入采用临时文件加原子替换；数据库记录和本地文件必须成对成功。
- 权限错误只影响截图，不改变会议状态机。
- Notion 上传或替换失败不删除本地原图、不清空旧页面、不标记错误快照为已同步。
- 迟到的截图或笔记异步结果必须验证活动 meeting ID，不能写入已经结束或新开始的会议。
- 删除会议对附件采用可恢复、幂等的清理语义；清理失败可在后续维护中重试。

## 测试策略

### 单元测试

- 笔记创建时间戳、每次输入自动保存、失败重试、编辑和删除。
- 截图目标显示器选择、文件落盘、记录创建、失败回滚和会议级联删除。
- 转录、笔记和截图的稳定时间轴排序。
- 结束会议或重启应用后的数据恢复。
- 用户笔记进入总结和完整纪要输入。
- DeepSeek 请求不包含任何截图字段或派生信息。
- JPEG 压缩输出不超过 4.5 MiB，并始终在临时目录生成。
- Notion 时间轴区块顺序、图片上传失败保护、再次同步替换且不重复。
- FluidAudio 管理器使用精确阈值 0.7045655。

### 回归测试

- 现有会议编辑、自动保存和精确批量替换。
- Notion 管理区块替换和用户内容保护。
- Sparkle 更新、高精度模型准备、音频诊断和录制状态机。
- 完整 MeetingNotesTests 和可运行的 UI 测试。

### 实际 Beta 验收

- 实际打包的 Beta 中录制会议时新增、编辑和删除笔记。
- 鼠标分别置于目标显示器后截图，确认时间和显示器正确。
- 重新打开会议后笔记和截图仍存在。
- 重新生成总结和纪要，确认笔记内容被正确使用。
- 连续两次同步 Notion，确认旧内容被替换而非叠加，截图可见。
- 至少两名真人参与的线下会议，确认说话人不再明显合并。
- 回归检查更新、模型下载、麦克风、智能诊断及会议开始/结束。
