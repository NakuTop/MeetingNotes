# MeetingNotes 音频设备选择与智能诊断设计

## 背景

MeetingNotes 当前依赖系统默认麦克风。线下录音使用
`AVAudioEngine.inputNode`，线上录音使用 ScreenCaptureKit 同时采集麦克风与系统
声音。应用没有显示实际使用的设备，也不会检测持续无音频帧或全零样本。

在另一台 Apple Silicon Mac 上，麦克风可由 FaceTime 正常使用，但
MeetingNotes 的线下录音、线上麦克风轨和线上系统声音轨均无声。当前发布包
没有 Developer ID 签名，因此应用无法绕过或自动修复 macOS 的隐私授权，但
可以通过明确选择设备、端到端自检和通俗诊断，避免静默生成无声录音。

## 目标

- 在设置中选择 MeetingNotes 使用的输入和输出设备。
- 输入选择同时应用于线下录音和线上麦克风轨。
- 输出选择只影响 MeetingNotes 的测试音和录音回放，不修改系统默认输出。
- 提供麦克风实时音量测试与输出测试音。
- 提供约 8 秒的引导式端到端诊断。
- 先由本地确定性规则判断事实，再由 DeepSeek 生成简短中文说明。
- 诊断必须由用户手动发起、预览并确认上传。
- 不上传、保存或生成测试录音、会议音频和转录内容。
- DeepSeek 不可用时仍显示本地诊断结果。

## 非目标与平台限制

- 不尝试绕过、授予或重置 macOS 麦克风与屏幕录制权限。
- 不在录音过程中静默切换输入设备。
- 不修改 macOS 全局输入或输出设备。
- 不让 DeepSeek 判断音频帧、音量或权限等客观事实。
- 不承诺在没有 Developer ID 的情况下消除所有 TCC 身份问题。
- 不在录音进行中运行诊断或抢占音频设备。

## 方案选择

采用“本地确定事实，DeepSeek 负责解释”的混合方案。

本地代码负责采集结构化证据、执行确定性规则并生成基础结论。DeepSeek
只接收脱敏后的白名单 JSON，把已经确定的结论转换为简短、通俗的中文问题和
解决方案。相比上传原始日志让模型判断，这种方式更准确、可测试，且在 API
失败时仍然可用；相比完全本地诊断，它能更自然地解释少见的设备组合和系统
状态。

## 架构

### 音频设备目录

新增音频设备目录服务，提供输入和输出设备快照。

输入设备通过 AVFoundation 发现，并使用 `AVCaptureDevice.uniqueID` 作为
持久标识。设备条目至少包含：

- 稳定 ID
- 本地化名称
- 设备类型与制造商
- 是否连接
- 是否挂起
- 是否被其他应用占用
- 是否为系统当前默认设备

输出设备通过 Core Audio 枚举，并使用
`kAudioDevicePropertyDeviceUID` 作为持久标识。设备条目至少包含：

- 稳定 UID
- 显示名称
- 是否可用
- 是否为系统当前默认输出

设备连接或断开后刷新目录。设置中同时提供“跟随系统默认”选项。

### 设备偏好

`AppSettingsStore` 保存可选的输入设备 ID 与输出设备 UID。空值表示跟随系统
默认。

应用启动和录音开始前解析保存的设备：

- 保存的设备存在时继续使用。
- 保存的设备不存在时回退系统默认。
- 回退必须在界面中明确提示，并更新诊断状态。
- 不因为临时断开而删除原选择，设备重连后允许用户恢复。

### 线下麦克风采集

将只依赖系统默认设备的 `AVAudioEngine.inputNode` 采集改为基于
`AVCaptureSession` 的明确设备采集：

- 通过保存的 `AVCaptureDevice.uniqueID` 创建输入。
- 通过音频数据输出接收 `CMSampleBuffer`。
- 复用现有 PCM 转换、写入与转录数据结构。
- 保留现有背压、停止、暂停和错误传播语义。

这样设置页测试、线下录音和线上麦克风可以共享同一个设备身份。

### 线上分轨采集

线上录音继续使用 ScreenCaptureKit：

- 系统声音仍由 `.audio` 输出提供。
- 麦克风仍由 `.microphone` 输出提供。
- 将所选输入设备 ID 设置到
  `SCStreamConfiguration.microphoneCaptureDeviceID`。
- 分别统计麦克风轨和系统声音轨的帧数、RMS 与峰值。
- 单轨故障必须被标记，不能伪装为双轨成功。

同时修正权限探测：ScreenCaptureKit 不可用不能再被当作已授权。不可用、
拒绝和探测失败必须保留为不同的内部状态，并映射为通俗提示。

### MeetingNotes 输出路由

录音回放继续使用 AVFoundation，但设置
`AVPlayer.audioOutputDeviceUniqueID`：

- 空值使用系统默认输出。
- 指定值仅影响 MeetingNotes 的 AVPlayer。
- 输出测试音使用相同路由。
- 不修改系统默认输出，不影响会议软件、音乐或其他应用。

### 设置界面

在设置中新增“音频设备与诊断”区域：

- 输入设备下拉框
- 实时输入音量条
- “测试麦克风”按钮
- 输出设备下拉框
- “播放测试音”按钮
- “智能诊断”按钮
- 最近一次诊断结果与时间

设备测试与智能诊断不能在正式录音进行中启动。设备列表变化时，界面实时更新
可用性与回退提示。

## 引导式智能诊断

智能诊断由用户点击后开始，总时长目标约为 8 秒：

1. 检查麦克风和屏幕录制权限。
2. 检查已选设备是否存在、断开、挂起或被占用。
3. 通过所选输出设备播放短测试音。
4. 询问用户是否听到测试音。
5. 提示用户说一句话，并测量输入帧数、RMS 与峰值。
6. 使用临时 ScreenCaptureKit 配置检测系统声音轨是否能捕获测试音。
7. 立即停止临时流并恢复原设置。
8. 运行本地规则，生成结构化诊断结论。
9. 展示脱敏摘要，等待用户再次确认。
10. 将白名单 JSON 发送给 DeepSeek，并显示简短结果。

测试音只在内存中生成和播放。麦克风与系统声音的测试样本只用于实时统计，
测试结束即释放，不写入文件、不进入转录队列。

## 本地诊断规则

规则引擎至少覆盖：

- 没有音频帧：采集 API、权限身份或设备路由异常。
- 有帧但持续接近全零：设备静音、输入音量过低或选错设备。
- 麦克风正常、系统声音失败：屏幕录制权限或 ScreenCaptureKit 异常。
- 系统声音正常、麦克风失败：输入设备或麦克风权限异常。
- 两轨均正常但历史录音无声：写文件或播放链路异常。
- 测试音已发送但用户听不到：输出设备、音量或物理连接问题。
- 已选设备消失：回退系统默认并提示重新选择。
- 设备被占用：提示关闭可能独占设备的应用后重试。
- DeepSeek 不可用：显示本地结论和操作步骤。

阈值必须可测试，并以连续时间窗口而非单个样本判断静音，避免环境短暂停顿
造成误报。

## 诊断数据与 DeepSeek

### 白名单数据

诊断请求只允许包含：

- 应用版本
- Mac 型号类别与 macOS 版本
- 权限状态枚举
- 输入和输出设备的脱敏显示名称、类型与连接状态
- 所选设备是否为系统默认
- 各轨收到的帧数
- 分桶后的 RMS 与峰值等级
- 采样率与声道数
- 采集 API 错误类别
- 本地规则生成的问题代码与建议代码
- 用户是否听到测试音

禁止包含：

- 录音或测试音频样本
- 转录、总结、会议标题或书签
- API Key、Notion 凭据或其他密钥
- 用户名、绝对文件路径或会议文件名
- 任意原始系统日志

设备名称必须截断、控制字符过滤并作为数据编码，不能拼接成可改变提示词结构
的自由文本。

### DeepSeek 响应

要求 DeepSeek 返回严格结构化响应：

```json
{
  "issue": "简短问题说明",
  "solution": "一到两步解决方案"
}
```

客户端验证字段、长度和 JSON 类型。超时、网络错误、限流、格式错误或空响应
均回退本地诊断。模型输出不改变设备设置、不打开权限，也不自动执行系统操作。

## 错误处理与恢复

- 诊断开始前验证当前没有录音生命周期操作。
- 每个诊断阶段都有明确超时和取消点。
- 取消、超时、设备断开或应用退出时，停止所有测试流并释放设备。
- 诊断使用临时采集对象，不复用或污染正式会议写入器。
- 权限被拒绝时显示对应的“打开系统设置”按钮。
- 设备断开时保留原选择，但当前操作回退或失败必须明确显示。
- 正式录音开始后持续监测帧到达；长时间无帧时提示采集故障。
- 在线单轨故障保留另一条可用轨，并在会后详情中标记降级原因。
- 不因为 DeepSeek 失败而阻塞设置、测试或正式录音。

## 验证策略

### 自动化验证

- 输入、输出设备枚举与稳定 ID 映射。
- 设备选择保存、恢复和缺失设备回退。
- 线下录音使用指定输入设备。
- 线上配置设置指定麦克风设备并保持系统声音分轨。
- AVPlayer 使用指定输出设备 UID。
- 帧数、RMS、峰值和持续静音判断。
- 麦克风失败、系统音频失败、双轨失败和输出无声的规则矩阵。
- 诊断请求白名单与禁止字段测试。
- 设备名称截断和转义测试。
- DeepSeek 成功、超时、网络错误、无效 JSON 和空响应回退。
- 诊断取消、设备断开和退出时资源释放。
- 录音进行中禁止启动诊断。

### 真机验收

- 使用内置麦克风完成输入测试。
- 切换输入设备后完成线下录音。
- 指定输出设备播放测试音和历史录音。
- 在线诊断分别确认麦克风轨与系统声音轨。
- 关闭权限后识别问题并打开正确的系统设置页面。
- 拔掉已选设备后回退默认设备并提示。
- DeepSeek API 可用和不可用两种情况。
- 确认测试过程没有生成或上传音频文件。

## 完成标准

其他用户不需要终端命令，即可在设置中：

- 选择 MeetingNotes 的输入和输出设备；
- 验证麦克风、输出和在线系统音频是否工作；
- 看到具体失败环节；
- 通过手动触发的 DeepSeek 诊断获得简短问题与解决方案；
- 在 API 不可用时仍获得本地解决建议。

没有 Developer ID 时，首次授权仍由 macOS 控制，但应用不得再静默接受空采集
并生成完全无声的会议。
