# 2026-09-07 长会议性能补强

沿用用户已批准的原生界面、窗口截图和四小时／3,000 段目标；用户授权继续优化并要求加速。所有改动保留在 `codex/beta-1.3.1-performance`，本轮交付本机 Beta 1.3.1 (20)，人工复测后再决定发布。

## 本轮范围与证据

1. 文档基准快照：总结、纪要每键解码整个已保存文档，100 次双文档输入实测增加 200 次解码。缓存以文档 ID、正文 revision 和建议标题失效；保留自动保存、恢复原文及外部内容更新语义。
2. 多草稿保存：12 处编辑一次 flush 原先完整刷新 12 次。成功或部分失败后用 defer 统一刷新一次，已保存内容可见、未保存草稿保留。
3. 同说话人长发言：3,000 段原先持续复制累计文字和 IDs；同机 Debug 基准平均 0.527 秒（0.544348 / 0.535735 / 0.501138）。使用可变累积器，成组后一次拼接。尾部追加复用已有 turn；相同 startTime 的歧义排序保守全量重建。
4. 原生编辑器：100 次相同样式更新原先触发 200 次 NSTextStorage 属性编辑。样式值未改变时跳过 setter；已知宽度跳过无用的 10,000 点宽度预测量。覆盖选区、中文 marked text、实际样式变化与未知宽度回退。
5. 截图 PNG：相同 ImageIO 编码处理合成 3456 × 2234 图像约 35–44 毫秒。编码沿同一调用任务离开 MainActor，前后检查取消，保持无损 PNG、尺寸和像素数据。
6. UI 验证：原滚动 helper 只能向下滚，返回顶部摘要时可能失配。改为按目标位置双向滚动，编辑前等待可命中，保留真实流程和断言。

## 验证记录

- 修改前整套：1,278 单元 + 12 UI，0 失败，退出码 0。
- 新增红测：31 测试，6 个预期失败，确认文档解码、批量投影、重复排版/测量、PNG 主线程/迟到取消问题。其余语义测试通过。
- 最终全量单元：1,296 通过、0 失败，退出码 0。
- 最终整套：1,296 单元通过；12 UI 中 11 通过、1 失败，退出码 65。失败发生于 `testEditsAutosaveAndReplaceCurrentMeeting` 的输入动作：XCTest 默认 basic-alert monitor 访问临时 Dialog 的 Button 0 时辅助功能元素身份失效，中文输入事件尚未发送。不能将整套记为通过，也不能据此认定弹窗来自输入法或纠错。
- 失败用例不改代码独立复跑：1 通过、0 失败，77.690 秒，退出码 0。原失败记录保留；复跑不能覆盖整套退出码 65。xcresult 层级另确认目标编辑器底部 7pt 被视口裁切，`isHittable` 不代表完整可见；后续测试稳定性改进可要求完整进入视口并留边，不修改用户输入法或生产纠错设置。
- 3,000 段同说话人分组修改后同机 Debug 平均 0.014 秒（0.013576 / 0.013123 / 0.014499），相对原 0.527 秒约 38 倍；仅代表该分组操作，不代表整款应用提升 38 倍。100 次双文档输入无额外基准解码；12 处草稿 flush 只刷新投影一次；100 次相同原生样式更新无额外文本存储编辑。
- Beta 20 构建打包退出码 0。独立 `hdiutil verify`、挂载身份、`codesign --verify --deep --strict`、sandbox/audio-input/network.client、麦克风隐私文案、Sparkle 嵌入及 rpath 检查全部通过。
- 性能数据来自本地合成夹具，不能代替实际打包应用的长会议人工体验。
